# Abbott Law College Management System

## Overview

Abbott Law College Management System is a comprehensive institutional management platform designed for a law college in Mansehra, Khyber Pakhtunkhwa, affiliated with Hazara University. The system provides role-based access for seven distinct user types (admin, accountant, receptionist, teacher, library_staff, student, hazara_university) with features spanning student management, staff management, fee collection, attendance tracking, library operations, payroll, and financial reporting.

## User Preferences

Preferred communication style: Simple, everyday language.

## System Architecture

### Frontend Architecture

- **Framework**: React 18+ with TypeScript using Vite as the build tool
- **UI Components**: Shadcn/ui built on Radix UI primitives for accessible, customizable components
- **Styling**: Tailwind CSS with custom CSS variables for theming (light/dark mode support)
- **State Management**: TanStack React Query for server state management and caching
- **Routing**: Wouter for client-side routing
- **Form Handling**: React Hook Form with Zod validation via @hookform/resolvers
- **Design System**: Material Design principles adapted for institutional use with professional typography (Source Sans 3, IBM Plex Sans Condensed, JetBrains Mono)

### Backend Architecture

- **Runtime**: Node.js with Express.js
- **API Design**: RESTful APIs organized by feature domain (students, staff, fees, attendance, library, etc.)
- **Authentication**: Dual authentication system supporting both traditional username/password (Passport.js Local Strategy with bcrypt hashing) and Replit Auth (OpenID Connect)
- **Session Management**: Express-session with PostgreSQL session store (connect-pg-simple)
- **Authorization**: Role-based access control (RBAC) middleware protecting endpoints based on user roles
- **Build Process**: Custom build script using esbuild for server bundling with selective dependency bundling for optimized cold starts

### Data Storage

- **Database**: PostgreSQL (Neon serverless PostgreSQL)
- **ORM**: Drizzle ORM for type-safe queries and schema management
- **Schema Location**: `shared/schema.ts` contains all table definitions
- **Key Tables**: users, sessions, students, staff, studentAttendance, staffAttendance, grades, feeStructures, feeVouchers, feePayments, salaryTypes, salarySlips, libraryBooks, libraryIssues, libraryFines, expenseHeads, incomeExpense, notifications, visitors, inquiries, programs, courses, backups
- **Migrations**: Managed via Drizzle Kit with `npm run db:push`

## External Dependencies

### Database
- **Neon PostgreSQL**: Serverless PostgreSQL database (`@neondatabase/serverless`)
- Connection configured via `DATABASE_URL` or `NEON_DATABASE_URL` environment variable

### Authentication
- **Passport.js**: Authentication middleware with Local Strategy for username/password auth
- **bcrypt**: Password hashing (10 salt rounds)
- **Replit Auth**: OpenID Connect integration via `openid-client` for Replit-based authentication

### Key Runtime Dependencies
- **express-session**: Session management with PostgreSQL store
- **connect-pg-simple**: PostgreSQL session store adapter
- **drizzle-orm**: Type-safe database queries
- **drizzle-zod**: Zod schema generation from Drizzle schemas
- **date-fns**: Date manipulation utilities

### Frontend Libraries
- **@tanstack/react-query**: Server state management
- **wouter**: Lightweight routing
- **react-hook-form**: Form state management
- **zod**: Schema validation
- **recharts**: Charting library for dashboards
- **lucide-react**: Icon library

### Environment Variables Required
- `DATABASE_URL`: PostgreSQL connection string
- `SESSION_SECRET`: Secret for session encryption
- `PORT`: Server port (defaults to 5000)
- `ISSUER_URL`: (Optional) Replit Auth issuer URL
- `REPL_ID`: (Optional) Replit environment identifier
